# 脚本、分镜与拆解

## 按形式写作

| 类型 | 可用结构 | 重点 |
|---|---|---|
| 情绪独白 | 具体处境/痛点→角色回应→表情或停顿 | 一条只承载一个主要情绪；不硬塞完整五段式 |
| 采访 | 有针对性的问题→符合角色的意外回答→反应 | 问题也必须具体，避免泛泛“今天开心吗” |
| 任务喜剧 | 任务→性格导致的误差→后果→补救→关系落点 | 不规定三次事故；每次转折应来自前因 |
| vlog | 今日处境→生活动线→细节递进→自然收束 | 可用快乐/松弛替代冲突；避免不相关景点堆砌 |
| 成长连载 | 本集目标→选择与代价→本集解决→长期状态变化 | 本集有满足，后续有空间，不必每集断在悬崖 |
| 视觉救援 | 一眼可懂的危险→行动受阻→解法→情感回报 | 因果优先于特效数量；儿子也可主动救父 |

时长是设计变量。原资料的11秒、60–90秒、150秒及6分钟均是案例/提议，不能当所有作品的限定。先用口读/试配音校准，再核对镜头时长；对白长时减少动作或延长时长，不把大量台词硬塞3秒。

## 输出分镜

镜号｜预计秒数｜景别/构图｜主体及单一主要动作｜台词/旁白｜声音/停顿｜情绪目的｜一致性锚点｜生成风险及替代拍法。

原创稿中的秒数写“设计时长”，不得伪装为参考原片的测量时间。配乐用气氛或功能描述；用户需要具体曲目与版权时再查可用素材。

## 拆解素材的七维框架

开场吸引点、事件结构、节奏/转折、情绪兑现、角色关系、结束方式、制作特征。先记录每维的证据类型：看过原片才记录实测镜头与声音；只有字幕就分析台词和事件；只有标题则限于题材与标题策略。

输出三列：可观察事实｜解释/机制假设｜可原创迁移的做法。解释不是因果证明。只凭高赞视频不能断言某种结构必然提高完播或涨粉。

## 改稿检查

用具体改写解决问题。例如“开头更抓人”应替换成一条实际开场；“角色没立住”应给一个符合其欲望的动作；“太贵”应改场景数、镜头复杂度或呈现方式。保留用户风格，不把所有内容都改成奶凶吐槽。
