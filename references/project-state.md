# 项目持久化与恢复

技能安装本身不会记住每个账号。持续IP任务把状态保存在用户当前项目，而非技能库。优先用用户指定目录；否则遵循当前工作区输出规则，在允许的交付目录下建`ai-pet-projects/<账号短名>/`。同一账号复用现有目录；多个账号不混写。目录不明且存在多个候选时再问用户选哪一个。

## 初始化与文件用途

首次正式持续开发时，从[IP手册模板](../assets/ip-bible-template.md)和[连续性模板](../assets/continuity-template.md)复制为`ip-bible.md`和`continuity.md`，填入已知事实、用户决定与明确的草案。不要覆盖已有文件。

按实际任务创建：
- 视觉任务时用[角色视觉规范模板](../assets/character-visual-template.md)建立`characters/<角色ID>/visual-spec.md`；图像、提示词和检查记录保存到对应角色目录，复用现有项目路径，不为模板强制迁移已有文件。
- `topics.csv`：使用[选题表](../assets/topics-template.csv)字段；T编号稳定，重写保留ID并更新说明，合并保留指向。
- `episodes/`：每集文件命名如E001-v1.md，包含脚本/分镜及状态，实质修订留新版本。
- `performance.csv`：使用[数据表](../assets/performance-template.csv)字段；未知留空，每个平台和观察时点独立一行。
- `next-session.md`：本轮交付、采用版本、待解决问题、下次建议和必要文件路径。

单次聊天没有文件工具时交付可复制的状态块，明确尚未保存；绝不声称已持久化。

## 状态语义

选题：候选→入选→写稿中→待制作→已发布，另可暂缓/合并/否决。写完脚本只到写稿完成/待制作，不算已发布。

剧集：草稿、已确认、已制作、已发布分别记录。计划排期不等于实际发布日期。用户明确采用的剧情进入已确认连续性；未经采用的建议单列候选，不改变正史。用户让你按假设直接完成方案时可完成全部草稿，无需每一步求批准。

写入前读现有文件，在原状态上增量更新；不重置未知历史，不覆盖用户改动。修改已确认设定须依据用户本次明确要求或已给出的决定；记录旧值、新值、理由和受影响剧集。

## 角色资产与版本同步

IP手册保存角色欲望、关系和声音，视觉规范保存同一角色ID的形象锚点与基准图版本。更新时互相引用，不在多个文件各维护一套冲突外形。候选图、已采用基准、已替换版本分开记录；用户已明确选定的版本可直接采用，不另设逐步审批。

视觉修正记录原因、变化区域和受影响镜头/剧集。局部新版本不自动重生成全部旧素材；只在用户所需范围修正，留下后续采用规则。生成成功不等于通过检查，通过静态图检查也不等于视频已验证。检查方法见[角色视觉开发与验收](character-visuals.md)。

## 恢复与结束

再次调用先读next-session和IP手册，再按任务读取连续性、相关旧集与选题表。无关历史不必全加载。

结束时报告真实保存位置、增加/修改内容及下一步。没有发布数据就保留复盘空白，不替用户编一轮效果。持续开发不等于后台自动运行；定时提醒或周期生成只有用户明确提出时才配置自动化。
